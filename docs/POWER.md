# 电源、休眠与 E Ink 刷新

KDash 只做它能证明的事情，不承诺硬件无法实现的后台行为。

## 1. 运行时框架状态

launcher 在启动 KDash 前停止 `lab126_gui`（upstart）或 `/etc/init.d/framework`（sysv），退出时重启。

原因：

- 原生框架会持续重绘状态栏/时钟/弹窗，覆盖 KDash 的 framebuffer。
- 停止框架后，KDash 拥有完整屏幕，退出路径可控。

影响：

- Kindle 原版阅读界面暂时不可用；退出后恢复。
- 书库 scriptlet 的运行者（SH_Integration）属于框架；停止框架会结束它，KDash 继续运行。
- Wi-Fi 由 `wifid` 管理，通常不随框架停止；但不同固件可能有差异，**不保证**休眠后仍在线。
- 不能用 KUAL 停止 KDash（未安装 KUAL）；用界面 X 退出或重启设备。

## 2. `preventScreenSaver`

- 启动时 launcher 记录原值，并设置为 `1`。
- App 根据 `power.keep_awake` 策略再次设置。
- 退出时 launcher 恢复原值。
- 它只影响“空闲进入屏保/休眠”的策略，不修改系统休眠配置文件，也不改变低电量保护。
- 即使设为 1，某些固件仍可能在长时间无操作后挂起 CPU；这时屏幕保持最后画面，定时器暂停。

策略：

| 值 | 行为 |
|---|---|
| `plugged`（默认） | 仅外接电源时保持唤醒；电池时允许原生休眠 |
| `always` | 始终请求保持唤醒（耗电更高） |
| `never` | 不请求保持唤醒；屏幕仍会保留最后画面，直到系统休眠 |
| `battery` | 仅电池时保持唤醒（实验性） |

设备内 Settings 页可以循环切换策略；也可以编辑 `config.json`。

## 3. 屏幕保持与休眠的区别

必须区分四件事：

1. **画面保持**：E Ink 断电后仍显示最后图像。KDash 退出/休眠不会主动清屏。
2. **CPU 运行**：休眠后 CPU 暂停，Lua 定时器不会执行；没有 RTC 唤醒，KDash 不能保证准点刷新。
3. **网络保持**：Wi-Fi 可能被系统关闭；醒来后需要重新连接。
4. **应用恢复**：如果系统进入休眠，KDash 没有收到唤醒事件的处理逻辑（v0.1）；唤醒后可能继续旧循环或需要重新启动。

因此：

- Clock 每分钟刷新只在 CPU 清醒时成立。
- 天气/Dida 的后台同步不是硬实时；休眠期间不会联网。
- 不修改系统级休眠逻辑，不承诺“永远在线”。

## 4. 刷新策略

- 局部刷新：`A2` 波形，刷新变更的卡片区域。
- 页面切换/首次绘制：全屏 `GC16`。
- 每 `power.full_refresh_every`（默认 24）次局部刷新做一次全屏 `GC16`，清理残影。
- 脏区域合并：相邻文本/填充区域合并，减少刷新次数；超过 5 个区域时合并为一个区域。
- 内容未变化时模块不请求重绘。

实机需要观察：

- 每分钟刷新时钟卡片是否残影明显；如明显，降低 `full_refresh_every`。
- `A2` 是否导致文字发灰；如严重，改用 `GL16`/`GC16`（需改 `platform/kindle/display_fbink.lua` 或增加配置）。
- 全屏刷新闪烁是否可接受；E Ink 特性，无法完全避免。

## 5. 电量

粗略影响因素：

- Wi-Fi 同步频率（Dida 15 分钟、天气 45 分钟）。
- 是否 `keep_awake=always`。
- 屏幕刷新次数（E Ink 刷新本身耗电）。
- 框架停止不直接省电；省电主要来自减少唤醒与网络。

建议：

- 桌面常驻且插电：`plugged` + 天气 60 分钟、Dida 30 分钟。
- 电池使用：`never` 或 `plugged`，降低同步频率，接受休眠后不刷新。
- 低于 20% 时系统可能强制休眠；KDash 不做对抗。

## 6. 退出与恢复

- 正常：X → 确认 → Lua 清理 → launcher 恢复框架 → 书库。
- 异常：Lua 报错/退出 → launcher trap 恢复框架。
- `SIGKILL`/断电：launcher 无法恢复；重启设备，框架开机自启。
- 如果框架卡住：SSH `cd / && start lab126_gui`，或重启。

## 7. 不做的事

- 不 remount rootfs，不修改 `/etc` 休眠配置。
- 不修改前光（可选扩展需先确认 sysfs/LIPC 路径）。
- 不承诺后台定时唤醒。
- 不占用多个全屏应用并存；KDash 运行时框架停止，属于互斥前台会话。
